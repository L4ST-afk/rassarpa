# 逐字光学修正（灰度平衡 / 墨迹居中）

> 工具：`tools/glyph_optical_correct.py`
> 适用：把一组字形按「灰度平衡」做逐字光学微调——把每个字形的**墨迹几何中心**对齐到目标点，而非默认按其 advance 字身框居中。
> 来源原理：知识地图 A.1（字面率·重心·字怀）、A.4（方/圆/三角/菱四个基础形状视觉大小不等，须以最小者为基准统调）。

## 一、为什么需要它

同一字号的字形，两个物理量并不相等：

1. **墨迹面积（字面率）不同**：`1` 的墨迹远小于 `8`。直接同字号同位置摆放，网格里 `1` 发飘、`8` 显重——这就是「灰度不均」。
2. **墨迹中心偏离字身框中心**：尤其 `1` 的墨迹偏左。以 advance 框居中会让它看起来歪。

诊断法（与 skill 执行步骤 6 一致）：把样张缩到 50% 看整体灰度是否均匀，不均处即需光学修正。

## 二、两种模式

| 模式 | 是否改字号 | 做法 | 适用 |
|---|---|---|---|
| `fixed` | **否** | 仅横向墨迹居中：单字 `x = cx - inkCxGap_px`（text-anchor=middle）；两位数按「合墨跨度」居中并保留字间死隙收紧 | 样张、网格、徽标，**不希望扭曲字面**时 |
| `size` | 是 | 按墨迹面积等比缩放字号（轻字放大、重字缩小），逼近均匀灰度 | 仅作参考；样张全量等灰度会失真 |

## 三、灰度平衡与「字号」的边界（重要）

- **不改变字号**时，能做的灰度平衡只有「墨迹居中」这一纯量杠杆——它修正的是*位置*带来的观感偏差（偏左、不居中），**不能**改变单字本身的墨色轻重。
- 要真正拉平*墨色*（黑度），必须改变**字重**或**字面大小**，三选一：
  1. 变量字体 weight 轴（Helvetica Neue 为静态 .ttc，无变量轴）；
  2. 给轻字换 Bold 字面（连形状一起变，样张混重通常不美）；
  3. 转轮廓（paths）后加 stroke。
  三者都超出 `<text>` 节点结构，需重写渲染管线。**故固定字号下的灰度平衡 = 墨迹居中，而非墨色拉平。**

## 四、纵向说明

数字共用 cap height，墨迹纵向跨度一致（0 → capHeight）。用 cap-height 偏移做基线已使所有数字纵向统居中，**无需逐字纵向修正**。

## 五、用法

```bash
# 查看数字 0-9 在 75px 下的修正参数（fixed 模式，不改字号）
python3 tools/glyph_optical_correct.py \
  --font /System/Library/Fonts/HelveticaNeue.ttc --face 0 --size 75 --mode fixed

# 输出 JSON（供生成脚本 import 或直接消费）
python3 tools/glyph_optical_correct.py --font FONT --size 75 --json

# 参考：size 模式下的面积等灰度缩放（通常不用于样张）
python3 tools/glyph_optical_correct.py --font FONT --size 75 --mode size
```

生成 SVG 时，在脚本里 `import glyph_optical_correct as G`，用：
- `G.enrich(G.load_metrics(font, face, "0123456789"), size)` 取每字 `fixed_xshift_px`；
- `G.pair_layout(d1, d2, cx, size, tighten, M)` 取两位数两 `<tspan>` 的 `x`。

## 六、落地检查清单

- [ ] 单字：`text-anchor="middle"` 时 `x = cx + fixed_xshift_px`（主要修正 `1` 偏左约 4px@75）。
- [ ] 两位数：用 `pair_layout` 取代按 advance 居中，使合墨跨度对准圆心；保留 `tighten`（默认 0.7，即吃掉 70% 死隙、留 30%）。
- [ ] 字号、字重、颜色、圆/描边/网格布局一律不动（固定字号约束）。
- [ ] 输出经 XML 解析校验；缩到 50% 目视灰度是否更匀。
