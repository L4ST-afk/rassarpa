# 测量方法

本仓所有数字都来自 `tools/probe.html` 的一次真实渲染，不是从规范里抄的取值。复跑一条命令：

```bash
node tools/measure.mjs
# 换浏览器：只有能 --dump-dom 的才能用，Chrome／Chromium 系；Firefox 不支持这个开关
CHROME="/path/to/Chromium" node tools/measure.mjs
```

结果写进 `results/<浏览器>.json` 与同名 `.md`；`results/` 里现存的读数即下面这张表的出处。

## 三对照法

任何一个「属性是否生效」的问题，都要三种状态同时量，缺一条都会得错结论：

1. **显式关闭**（`no-autospace`）
2. **显式开启**（`normal`）
3. **完全不声明**

实测结论：「不声明」与「显式关闭」量出来一模一样，差值为 0 —— 所以**不声明等于关闭**。只量「不声明」与「开启」这一组的人，会把「默认关闭」错记成「默认开启、只是没写」。

## 两个必须避开的测法陷阱

- **不要在串里带空格。** `中 a 中` 加不加 `normal` 差值恒为 0，因为规范规定已有空格处不再补。要用 `中a中` 这种无空格串。
- **不要用 `CSS.supports()` 代替渲染。** 三款中文字体（苹方／宋体／黑体）对 `text-spacing-trim: normal` 全部返回 true，实际只有苹方挤得出 −16px。属性「被识别」与「产出变化」是两件事。

## 量什么

- **单边界**（`中a`）：量 `getBoundingClientRect().width` 的差，两种字号各一次——比例恒定才说明是 em 单位。
- **`.mx` 盒**：同一个串插入一个 `display:inline-block; width:.25em; height:0` 的空元素，量差。
- **跨元素边界**（`中<abbr>a</abbr>中`）：与纯文本同串对照，看引擎是否在元素缝处补间隙。
- **挤压**：同一串分别用 `text-spacing-trim: space-all` 与 `normal`，每款字体各一对。

## 已知限制

- 只量 advance（排版宽度），不量墨迹；逐字光学修正另见 [../references/逐字光学修正.md](../references/逐字光学修正.md)。
- 测量只覆盖 macOS 上的 Chrome（headless 158）一条通道。Safari 与 Firefox 未实测，Windows 字体环境也没有；`results/` 里没有它们的读数，就是没有跑过。
- 读数随字体与引擎版本变化；换机器后必须重量，⛔ 不要把本仓的读数当自己机器的结论。
