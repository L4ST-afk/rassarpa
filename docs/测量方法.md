# 测量方法

本仓所有数字都来自 `tools/probe.html` 的一次真实渲染，不是从规范里抄的取值。复跑一条命令：

```bash
node tools/measure.mjs
# 换浏览器：只有能 --dump-dom 的才能用，Chrome／Chromium 系；Firefox 不支持这个开关
CHROME="/path/to/Chromium" node tools/measure.mjs
```

结果写进 `results/<浏览器>.json` 与同名 `.md`；`results/` 里现存的读数即下面这张表的出处。

## 另外两家引擎怎么量

Chrome 有 `--dump-dom`，一行命令就够。Firefox 与 Safari 没有这个开关，各走一条：

| 引擎 | 命令 | 拿到的是什么 | 能不能进 CI |
|---|---|---|---|
| Firefox 159 | `node tools/measure_pw.mjs --engine firefox` | Playwright 下载的官方构建 | 能（Ubuntu runner） |
| WebKit 27.2 | `node tools/measure_pw.mjs --engine webkit` | Playwright 的 WebKit 构建 | 能（同上） |
| Safari 本体 | `node tools/measure_safari.mjs` | 你机器上那个真 Safari | 不能，要开开关、要有人点 |

Safari 那条要先把两个开关各开一次：

```bash
sudo safaridriver --enable        # 开 WebDriver 支持，要管理员密码
# Safari → 设置 → 高级 → 勾「显示开发菜单」→ 开发 → 允许远程自动化
node tools/measure_safari.mjs
```

**构建不等于本体。** Playwright 的 WebKit 是引擎实现，能回答「引擎给不给这道缝」，回答不了「Apple 发的 Safari 现在是不是这样」。两者读数分别落盘，引用时分清。

三家在同一 probe 下的实测对照（2026-11-20，macOS）：

| 读数 | Chrome 158 | Firefox 159 | WebKit 27.2 |
|---|---|---|---|
| 单边界间隙 | 0.125 em | 0.125 em | 0.125 em |
| 不声明 vs 显式关闭 | 0 | 0 | 0 |
| 跨元素边界（两缝） | +8px | +8px | +4px（只补一侧） |
| 每缝包空 span | 0 | 0 | −4px（把原生间隙打掉） |
| `text-spacing-trim` | 支持 | 不支持 | 不支持 |

## 三对照法

任何一个「属性是否生效」的问题，都要三种状态同时量，缺一条都会得错结论：

1. **显式关闭**（`no-autospace`）
2. **显式开启**（`normal`）
3. **完全不声明**

实测结论：「不声明」与「显式关闭」量出来一模一样，差值为 0 —— 所以**不声明等于关闭**。只量「不声明」与「开启」这一组的人，会把「默认关闭」错记成「默认开启、只是没写」。

## 两个必须避开的测法陷阱

- **不要在串里带空格。** `中 a 中` 加不加 `normal` 差值恒为 0，因为规范规定已有空格处不再补。要用 `中a中` 这种无空格串。
- **不要用 `CSS.supports()` 代替渲染。** 三款中文字体（苹方／宋体／黑体）对 `text-spacing-trim: normal` 全部返回 true，实际只有苹方挤得出 −16px。属性「被识别」与「产出变化」是两件事。

## 量什么

- **单边界**（`中a`）：量 `getBoundingClientRect().width` 的差，两种字号各一次——比例恒定才说明是 em 单位。
- **`.mx` 盒**：同一个串插入一个 `display:inline-block; width:.25em; height:0` 的空元素，量差。
- **跨元素边界**（`中<abbr>a</abbr>中`）：与纯文本同串对照，看引擎是否在元素缝处补间隙。
- **挤压**：同一串分别用 `text-spacing-trim: space-all` 与 `normal`，每款字体各一对。

## 已知限制

- 只量 advance（排版宽度），不量墨迹；逐字光学修正另见 [../references/逐字光学修正.md](../references/逐字光学修正.md)。
- 本体只量过 macOS 上的 Chrome（headless 158）。Firefox 与 WebKit 是 Playwright 构建，Safari 本体待跑 `tools/measure_safari.mjs`；Windows 字体环境完全没有读数。
- 挤压只在 Chrome 上量得出来：Gecko 与 WebKit 都不支持 `text-spacing-trim`，读数 0 是「属性没有」，不是「字体不挤」。上表那三款字体的差异，换引擎不成立。
- 读数随字体与引擎版本变化；换机器后必须重量，⛔ 不要把本仓的读数当自己机器的结论。
