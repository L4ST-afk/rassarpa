# 判据表

每条一行：主张、取值、成立条件、证据、怎么核验、什么时候失效。**离开条件引用这一行的结论，就是误用。**

证据只有三种：**实测**（`results/` 里有 JSON）、**引擎记录**（别人的报告，本仓未复现）、**实现约束**（由写法保证，量不到）。看这一列就知道能信到什么程度。

实测有两类来源，别混：`results/headlesschrome-*` 是 Chrome 本体；`results/firefox-pw.*`、`results/webkit-pw.*` 是 Playwright 起的两家引擎构建 —— WebKit 构建不等于 Apple 发的 Safari，Safari 本体要另跑 `tools/measure_safari.mjs`。

| # | 主张 | 取值／表现 | 成立条件 | 证据 | 核验方式 | 失效条件 |
|---|---|---|---|---|---|---|
| C1 | 不声明 `text-autospace` 等于关闭 | 与显式 `no-autospace` 差值 0 | Chrome 140+ / Firefox 145+ / Safari 18.4+（三家实现初始值均为 `no-autospace`） | **实测三家**：Chrome 158、Firefox 159、WebKit 27.2，差值都是 0 | 同一串三对照：无声明／`normal`／`no-autospace` | 引擎把初始值改成规范值 `normal` 的那天 |
| C2 | `normal` 的间隙宽 1/8 em | 32px→4px，64px→8px，比例恒定 | Blink、Gecko、WebKit | **实测三家**均为 0.125 em；WebKit 的「只在前侧」也量到了（见 C5） | 无空格串单边界量 advance 差 | 作者自行改 UA 样式、或引擎换取值 |
| C3 | 带 ASCII 空格的串差值为 0 | 加不加 `normal` 都一样宽 | 规范：已有空格处不再补 | **实测三家** | 同一串加空格与不加空格各测一次 | 用 `replace` 语义绕道时（Chromium 未实现） |
| C4 | 四分空（1/4 em）要自己给 | `.mx` 盒 32px→8px = 0.25 em | 需可插 DOM 的场合 | **实测三家**均为 0.25 em | 量 `中X` 与 `中<span class="mx"></span>X` 之差 | 目标媒介不给插 DOM（邮件、第三方编辑器） |
| C5 | 跨元素边界的缝，Chromium 与 Gecko 给两侧，WebKit 只给一侧 | 纯文本两缝：Chrome／Firefox +8px；WebKit +4px | Blink、Gecko 各侧都补；WebKit 只补一侧 | **实测**（Chrome 158、Firefox 159、WebKit 27.2） | 与纯文本同串对照 | WebKit 修好单侧限制的版本发布 |

| C7 | 挤压随字体而定，不看属性支持 | 苹方 −16px；宋体 0；黑体 0 | macOS 三款字体实测；`CSS.supports()` 对三款均 true | **实测 Chrome 158**；Gecko 与 WebKit 不支持 `text-spacing-trim`，谈不上字体差异 | `space-all` 与 `normal` 两档同串量差 | 字体本身带 `halt`／`vhal`（思源、苹方系） |
| C8 | 间隙不用字符实现 | 复制文本不含多余字符 | 任何走渲染层的实现 | **实现约束**，未实测 | 复制后粘贴比对 | 用 `U+0020`／`U+2009` 硬插的写法 |

## 两条使用纪律

- **一条结论不能跨条件推广。** C2 在 Blink/Gecko 成立，不等于在 WebKit 成立；C7 在苹方成立，不等于在宋体成立。
- **构建不等于本体。** `webkit-pw` 那份是 Playwright 的 WebKit 构建，能说明引擎行为，不能替代 Safari 本体。引用 Safari 结论时，要么标明「WebKit 构建」，要么等 `tools/measure_safari.mjs` 的读数。
